## 2023-10-27 - [Dynamic Disabled States in Staff Dashboard]
**Learning:** Buttons whose `disabled` property is dynamically managed via JS (like the Queue Control buttons `HOLD`, `RECALL`, etc.) can be visually indistinguishable from active buttons unless explicitly styled with `disabled:` utility classes. Furthermore, users, especially staff in high-pressure environments, need contextual help to understand *why* an action is currently disabled. Relying only on a subtle visual change isn't sufficient.
**Action:** Always pair dynamic JavaScript `disabled` state management with robust visual indicators (`disabled:opacity-50`, `disabled:cursor-not-allowed`) and semantic `title` tooltips that dynamically update to explain the restriction (e.g. "No active consultation to hold"). Ensure keyboard accessibility by testing `focus-visible` states explicitly alongside disabled styling.
